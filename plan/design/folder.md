# Проект исправлений folder — 02-01

## Границы и принятые решения

Основание: `plan/reviews/01-02.md`, находки 01–11; 12 (activity) вне области. Исходная реализация: `index.go` хранит указатели, `Scan` меняет индекс во время обхода, `applyOne` использует решение до download, `Lookup` отдаёт абсолютный путь. Go в `go.mod` — **1.26.5**, уже есть `golang.org/x/sys v0.49.0` и `x/text` для NFC. Новых зависимостей не требуется. Демон, JSON, HTTP/mTLS и векторы версий сохраняются.

Обязательная политика владельца:

* Исчезнувший или пустой корень при непустом индексе останавливает папку до явного подтверждения пользователя; автоматическое resume, рестарт и возвращение тома не снимают остановку.
* Существующий файл сохраняет локальные права доступа; новые файлы — 0644/0755. Передаётся только Exec; его изменение увеличивает версию.
* При конкурентных edit/delete побеждает edit. Причинно более новое удаление без конкурентной правки применяется обычно.

## Решения и инварианты

### Доступ к дереву (01-02-01)

Ввести закрытый `rootFS`, владеющий открытым дескриптором корня. Никаких `Join(Root, peerName)` с последующим абсолютным Open/Stat/Rename/Remove. Валидатор отвергает пустое имя, `.`, абсолютные пути, NUL, backslash, `..`, нечистые компоненты и не-NFC вход. `Disk` никогда не принимается от пира; загруженный из старого индекса также валидируется как относительный путь (ему разрешён NFD).

Выбран конкретный общий механизм Linux/macOS: `unix.Open` корня с `O_DIRECTORY|O_NOFOLLOW|O_CLOEXEC`; компоненты — `openat(parentFD, component, O_DIRECTORY|O_NOFOLLOW|O_CLOEXEC)`. При создании родителей — `mkdirat`, затем такой же `openat`, включая случай EEXIST. Финальный файл открывается `openat` с `O_NOFOLLOW|O_NONBLOCK`, затем `fstat`: допускается только regular file. Каталоги перечисляются через открытые fd; hash, chmod, timestamps, Sync работают по открытому файлу, а не по повторно разрешённому пути. Все fd закрываются. Неподдерживаемые special files не открываются для чтения тела.

Rename/unlink выполняются `renameat`/`unlinkat` по удерживаемым родителям; пустые каталоги — `unlinkat(AT_REMOVEDIR)`, без рекурсивного удаления. Удаление «мусора» родителей не нужно: непустой каталог оставляем. Симлинки не синхронизируем и не следуем им, включая `.sharedirignore`, tmp, recovery и conflict. Подмена компонента ссылкой после открытия не перенаправляет операцию на цель ссылки. Ошибка обхода блокирует операцию, а не включает fallback к абсолютному пути.

Установка **без перезаписи**: Linux `renameat2(RENAME_NOREPLACE)`, macOS `RenameatxNp(RENAME_EXCL)` (есть в текущем x/sys). ENOTSUP/неподдерживаемая ФС — ошибка и остановка операции, никогда обычный заменяющий rename. Для атомарной замены индекса обычный rename допустим: его каталог доверенный и сериализован.

`os.Root` доступен по версии, но не выбран: его методы разрешают внутренние симлинки, а здесь нужен единый запрет ссылок. Проверено по локальному `go doc os.Root`; API также предупреждает о гонках pathname Chmod/Chtimes. `EvalSymlinks` не является защитой.

Добавить `OpenVersion(name, hash)` → копия FileInfo и открытый `*os.File` вместо выдачи абсолютного пути. Проверяются состояние корня, canonical key, фактический Disk, regular type, hash/Exec и стабильность stat до/после чтения. Transport передаёт этот fd и закрывает его. Изменение во время передачи даёт retry/проверку хеша на принимающей стороне, а не чтение ссылки наружу.

Ограничение модели: fd защищает от перенаправления ссылкой, но процесс с правом перемещать уже открытый каталог может вынести сам каталог за дерево; hardlink тоже разделяет inode с внешним именем. Проверяем идентичность корня и цепочку родителей перед commit, при расхождении останавливаемся. Абсолютной изоляции от произвольного локального процесса с теми же правами этим добиться нельзя; это явно выделенный риск, не обещание sandbox. Не вводим привилегированный сервис.

### Полнота скана (01-02-02)

`Scan` под `scanMu` строит кандидат полностью отдельно от опубликованной map: имена, Disk, stat, hash, Exec, ignore. Ошибки ReadDir, Info, hash, чтения ignore (кроме ENOENT), изменение inode/stat при чтении отменяют **весь** кандидат. Старые files/clock/seq остаются неизменными, tombstone не появляется. Следующий watcher/периодический Scan повторяет попытку. Умышленно игнорируемые поддеревья не считаются пропавшими. Пропущенный special file на месте ранее индексированного regular file — ошибка типа, а не удаление.

Только после полного обхода и проверки корня строятся новые версии и удаления, затем долговечная публикация. Не полагаемся на size/mtime как доказательство неизменности: хешируем stable fd; это также находит запись с восстановленным mtime. При непрерывной записи скан может откладываться — безопаснее задержки, чем ложные удаления.

### Корень и остановка (01-02-03)

Хранить локальную привязку: очищенный абсолютный configured path, device/inode корня и schema version. При каждом Scan, перед применением после download и перед выдачей файла сверять текущий путь (без следования ссылкам) с удерживаемым fd. Отсутствие, иной inode/device/path, ссылка, не-каталог — `root_unavailable`/`root_changed`. При непустом индексе Open не создаёт отсутствующий корень. Первичная установка без индекса может создать каталог явно как bootstrap.

После полного обхода ноль учитываемых regular files при непустом `files` (включая индекс только с tombstone) — `root_empty`, без публикации удалений. Это намеренно консервативно; удаление последнего файла тоже требует подтверждения. Уход файлов под ignore также не должен обходить этот барьер.

Состояние `blocked` с кодом, сообщением, binding и случайным generation token сохраняется долговечно. Контрольный сервер остаётся жив, Status показывает `folder_error:{code,message,token}`. `/index` и `/file` возвращают 503 без индекса/байтов, runPeer отменяются; Kick будит long poll, который повторно проверяет блокировку. Scan не меняет индекс, Apply не коммитит даже уже скачанные tmp. Обычная pause независима и не сбрасывает блокировку. Ошибка сохранения также блокирует операции.

Новый control endpoint `POST /folder/confirm`, тело `{token, action:"reset"|"rebind"}`. Token связывает согласие с показанным состоянием; повторное применение старого token — 409. Под scanMu повторно проверить путь и тип, остановить/дождаться прежних runner/watcher, увеличить generation. `reset` архивирует старый индекс и начинает новый пустой индекс на проверенном корне; **не удаляет пользовательские файлы и не рассылает массовые tombstone**. `rebind` сохраняет индекс и связывает его с проверенным текущим корнем, затем делает полный Scan; подтверждённый пустой снимок разрешается ровно один раз, поэтому может опубликовать удаления. UI явно описывает разницу и запрашивает подтверждение. При отсутствии/ссылке подтверждение отклоняется. Новый binding/снятие latch сохраняются до resume. На сбое остаётся blocked, согласие не расходуется частично.

Reload при изменении cfg.Folder останавливает папку с root_changed; нельзя молча продолжать со старой папкой и новым Status. После перезапуска действует тот же барьер. Legacy индекс без binding при непустом files запускается blocked с предложением rebind/reset, а не автоматически доверяет пути.

### Применение и локальные писатели (01-02-04, 06)

Download происходит вне scanMu в уникальный закрытый tmp. После загрузки: scanMu → проверка ctx, generation, root → снимок текущей записи под mu → повторный `decide(cur,r,peer)`. Peer ID передаётся в applyOne, прежний step — только прогноз прогресса. Все ветви, включая mergeOnly и metadata-only, проходят этот путь. Если теперь нужна загрузка, которой нет, отпустить блокировку и перепланировать. Сравнение равного содержимого включает **Hash и Exec**. mergeOnly создаёт новую запись и копию Vector, не меняет опубликованный указатель.

До замены/удаления открыть текущий файл, проверить inode, hash, Exec и stat до/после; несоответствие индексу сначала регистрируется как локальная версия с tick, решение вычисляется заново. Параллельная правка побеждает tombstone, векторы объединяются так, чтобы решение не зацикливалось. Два runPeer с одинаковыми size/mtime и разными hash не обходят повторное решение.

Одна дополнительная hash-проверка не закрывает гонку с внешней записью. Поэтому **каждый** заменяемый/удаляемый inode сначала атомарно перемещается в уникальное recovery-имя в том же родителе без перезаписи, и только затем устанавливается tmp через no-replace. Если target появился в промежутке — оставить его, сохранить incoming/recovery, перепланировать. После capture повторно проверить захваченный inode: захваченное расхождение становится локальной правкой и сохраняется как видимый conflict. При удалении изменённый capture восстанавливается no-replace либо остаётся конфликтом, если имя уже занято.

Recovery-копии не удалять автоматически даже после совпадения хеша: внешний процесс может продолжать писать через ранее открытый fd. Имена recovery имеют служебный tmp-prefix и исключены из скана; журнал хранит их исходное имя. Сохранённый recovery доступен для ручного восстановления; при обнаружении изменения после commit следующий Scan продвигает его в обычный conflict. Это цена защиты несогласованных писателей; обещаем сохранение inode/байтов, а не снимок непрерывно меняющегося файла. Нельзя копировать capture и удалить оригинал: открытые fd писателя тогда потеряются.

Видимые conflict-файлы синхронизируются как обычные файлы. Имя: усечённый base + `sync-conflict` + короткий ID + hash версии + случайный суффикс + ext, с учётом NAME_MAX и NFC. Уникальность обеспечивается исключительно no-replace, при EEXIST выбирается новый суффикс. Это применяется и при promotion recovery; совпадение имени, наносекунд или хеша не разрешает перезапись. Для временных объектов — O_CREAT|O_EXCL, 0600.

### Имена (01-02-07)

Кандидат скана сначала строит NFC→фактический относительный Disk. При двух различных Disk с одним NFC ключом отменяется весь Scan с диагностикой обоих путей и блокируется Apply/выдача неоднозначного имени до успешного полного Scan. Не выбирать «последний» и не переименовывать молча. Один NFD файл разрешён: Name=NFC, Disk=NFD, даже при одинаковых метаданных изменение Disk обновляет mapping. На APFS учитывается фактическое перечисление, а не предположение о байтах имени.

Входящие `/index` записи с не-NFC Name отклоняются до download, считаются failed; `/file` принимает только canonical Name. Legacy загрузка проверяет дубликаты/невалидный Disk до map insertion; неоднозначность останавливает папку, не перетирает записи. Коллизии регистра остаются диагностируемой ошибкой без перезаписи.

### Снимки и долговечность (01-02-05, 08)

Порядок блокировок: **scanMu → saveMu → mu**; никогда наоборот. Все изменения files, clock, binding, blocked проходят транзакционный commit под scanMu, включая mergeOnly. saveMu берётся **до** снятия снимка, а не после; под mu глубоко копируются FileInfo, Vector, binding/error. Snapshot/Lookup тоже копируют Vector. I/O без mu; saveMu удерживается до завершения публикации. Generation снимка монотонна, старый снимок никогда не заменяет новый. Частичный save не считается успехом и не теряет dirty generation.

Для crash consistency нужен небольшой локальный JSON intent, не новый сетевой протокол. Один активный intent благодаря scanMu. Он содержит txID, ожидаемую/итоговую запись и generation, target, tmp/capture/conflict имена, binding; пути валидируются при recovery. Порядок:

1. Download: проверить размер/хеш; fd chmod/mtime, затем Sync файла. Для metadata-only подготовить новую копию inode, чтобы откат/открытые fd также были защищены.
2. Записать уникальный intent.tmp (0600), Sync, rename на intent.json, Sync каталога состояния. Без этого дерево не менять.
3. Capture старого inode no-replace, Sync родителя; установка incoming no-replace или отсутствие target при удалении, Sync каждого изменённого каталога, включая созданных родителей. Сохранить capture до любого разрушительного действия. Chmod/mtime нового файла уже сделаны и синхронизированы.
4. Сформировать кандидат индекса; уникальный tmp в каталоге индекса, полный Write, Sync, Close, rename → index.json, Sync каталога состояния. Только теперь опубликовать кандидат/seq и успешные Progress.Done/счётчик applied.
5. Удалить intent и Sync его каталога. Recovery inode остаётся сохранённым; запись о нём долговечна в локальном recovery manifest.

На старте **до Scan/сетевого обслуживания** восстановить intent: сравнить txID/generation индекса и фактические хеши; завершить зафиксированный commit либо сохранить обе стороны и blocked при неоднозначности. Не выводить из промежуточного отсутствия target tombstone или новую локальную версию. Если индекс уже commit, повторная обработка intent идемпотентна. Незавершённый Scan без изменений дерева может отбросить свой кандидат. После сбоя index-save текущая папка блокируется, intent остаётся; ошибки не только логируются. Никакого «успеха» после failed fsync.

На Linux — fsync файла и каталогов, на macOS дополнительно `F_FULLFSYNC` для долговечных файлов/intent/index; Sync каталогов обязателен. Неподдерживаемая долговечная операция даёт явную ошибку, не тихое обещание гарантии. Проверка на реальных ФС обязательна; гарантии ограничены исправным накопителем/ФС, соблюдающим flush.

### Права и размер (01-02-09, 10, 11)

Права доступа существующего файла (r/w для owner/group/other) сохраняются. Если Exec не изменён — сохранить все обычные rwx биты, 0600 остаётся 0600, 0700 остаётся 0700. При Exec false снять 0111; при переходе в true добавить execute только классам с локальным read: `(mode & 0444)>>2`. Поэтому 0600→0700, 0640→0750, 0644→0755; не добавляются r/w. Локальный Exec означает owner execute (`0100`, как сейчас). Это переносит boolean без расширения доступа к чтению. Новые файлы получают точно 0644/0755 после fd chmod; setuid/setgid/sticky не передаются и на новом inode не устанавливаются. ACL/xattr не входят в эту политику (см. риски).

Scan учитывает Exec даже при прежних size/mtime/hash и увеличивает Vector. decide не сливает разные Exec только по Hash. Metadata-only входящее изменение применяется без сетевой загрузки, но с тем же безопасным commit и сохранением локальных прав.

До планирования live-записи требуют Size>=0, корректный SHA-256; суммарный progress не переполняет int64 (checked sum). Tombstone не несёт тело; несовместимые поля не используются для аллокаций. После fetch folder проверяет **точное число** записанных байтов и hash, short/long body и ошибка Close/Sync отменяют commit и чистят tmp. Защитный counting writer прекращает запись сверх Size даже для тестового/другого Fetcher; без вычисления переполняющегося Size+1. Контракт 02-04: transport читает не более Size+1 и сообщает превышение, имеет idle timeout; folder не реализует повторно HTTP deadline. Size=MaxInt64 требует безопасной арифметики и в 02-04.

## Совместимость и миграция

`index.json`: локальная schema=2, прежние clock/files сохраняются, добавляются binding, generation, blocked, recovery metadata. Intent — отдельный JSON в каталоге состояния. Legacy (нет schema) сначала валидируется; файл архивируется атомарно до миграции, неоднозначные имена и неизвестная будущая schema — ошибка без перезаписи. Непустой legacy требует подтверждения binding; пустой можно bootstrap. Миграция идемпотентна и не меняет file vectors сама по себе. Downgrade не поддерживается: старый демон игнорирует защитные поля; для отката нужен архив и остановленная папка.

Формат `/index` FileInfo и `/file` query/body не меняются, Exec уже существует. Disk/binding/recovery никогда не отправляются. Старые пиры продолжают получать обычный JSON и bytes, понимают 503 через имеющуюся обработку недоступности. Они могут не распространять chmod-only до обновления: межверсионная гарантия Exec ограничена исправными пирами. Невалидный NFD от старого пира теперь failed с понятной диагностикой; автоматически нормализовать его опасно. Конкурентные edit/delete сходятся объединением векторов; README уточняет область конкуренции. Новые Status поля optional для старых клиентов; они не показывают объяснение, поэтому обновление UI входит в выпуск.

## Конкурирующие пути

Watcher — сигнал к полному Scan, а не источник tombstone; события во время транзакции объединяются и обрабатываются позже. Watcher плюс периодический Scan находят поздние записи в capture. Linux watcher не следует новым ссылкам при добавлении каталогов. Все runPeer проходят один scanMu commit; сеть вне блокировки, устаревшее поколение после pause/rebind отклоняется. Отмена проверяется повторно под блокировкой. Root reset/rebind дожидается завершения старого поколения, закрывает fd и запускает новый watcher. Внешние процессы не соблюдают mutex: capture/no-replace сохраняют их inode и новые имена. Рестарт сначала recovery, затем binding и полный Scan, только потом обмен. Ошибка питания в любой точке commit не превращается в скан промежуточного дерева.

## Задачи реализации

Каждая задача — один reviewable diff, ориентир **до 300 строк**, максимум 5 перечисленных файлов, включая новые тесты. Если бюджет не выдерживается, исполнитель останавливается для дополнительного разбиения, не расширяет ownership. Номера ниже зарезервировать в общем плане. Общая проверка Go: `go test -race ./internal/folder ./internal/app ./internal/transport`, Linux и macOS; платформенные сценарии запускаются на обеих ОС, cross-build не заменяет runtime-тест. Fault injection через небольшие внутренние интерфейсы, EACCES тест — непривилегированный процесс или инъекция, а не chmod под root.

### 02-10 — примитивы безопасного дерева, L3

## Риски и открытые вопросы владельцу

1. Без кооперации внешних писателей нельзя одновременно гарантировать мгновенную сходимость, ограниченное хранилище и сохранение записи через бесконечно открытый fd. Проект выбирает сохранение recovery inode без автоматической очистки. Нужны политика ручной очистки/retention и предел диска; до решения никакой автоматической сборки recovery. Это может заметно увеличивать расход места.
2. Какие ФС входят в поддерживаемую гарантию durability: APFS/ext4 как базовые; сетевые/exFAT и неподдерживаемый no-replace/dir-sync остаются явной ошибкой. Требуется подтвердить матрицу поддержки, особенно F_FULLFSYNC на целевых macOS/томах.
3. ACL, xattr, ownership и hardlink не представлены протоколом. Обычные mode bits сохраняются, но замена inode может изменить эффективные ACL. Для приватных ACL требуется отдельное решение владельца (копирование локальных ACL платформенными API или запрет обновления таких файлов); не обещать сохранение ACL в этом выпуске.
4. Dev/inode могут меняться после восстановления тома/снимка; консервативный rebind потребует подтверждения. Это не основание для автоматического обхода установленного владельцем барьера. Пустой корень и legacy миграция также требуют дополнительного действия пользователя.
5. Локальный процесс, перемещающий открытые каталоги/создающий hardlinks, находится вне строгой изоляции fd-подхода; нужна ли отдельная модель угроз с такими писателями, решает владелец. При необходимости абсолютного sandbox текущего дизайна недостаточно, расширение архитектуры здесь не заложено.
6. Case-fold коллизии, переполнение векторов и политика часов edit/edit не исправляются этим проектом. Обнаруженную неоднозначность не превращать в удаление; расширение модели имён/версий — отдельный проект.

Эти вопросы не пересматривают три обязательных решения; они ограничивают обещания о ресурсах, атрибутах и платформенных гарантиях.
