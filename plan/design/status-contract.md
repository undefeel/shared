# Контракт Status и подтверждения папки (итог 02-24)

Для задач 02-26 (CLI), 02-27 (macOS), 02-28 (Omarchy), 02-29 (README).

## GET /status — новые поля (оба необязательные, у старого демона их нет)

```json
"folder_error": { "code": "root_empty", "message": "…", "token": "…" },
"scan_error":   { "message": "…", "path": "dir/file.txt", "time": "2026-11-04T12:00:00Z" }
```

- `folder_error` — папка остановлена до решения пользователя. Синхронизация не идёт, пиры получают 503. Пауза/резюм и рестарт демона её не снимают.
  Коды:
  - `root_empty` — папка пуста, хотя раньше в ней были файлы (например, отмонтирован диск);
  - `root_unavailable` — папка недоступна или исчезла;
  - `root_changed` — путь к папке изменился или на её месте другая папка;
  - `commit_failed` — не удалось надёжно записать изменения на диск.
- `scan_error` — последний скан не прошёл (не удалось прочитать файл или подкаталог). Это не остановка: исчезает сама после первого успешного скана. Локальные изменения не отправляются, пока ошибка есть.

## POST /folder/confirm

Тело: `{"token": "<folder_error.token>", "action": "reset" | "rebind"}`.

- `reset` — начать заново с текущей папкой: старый индекс архивируется, начинается новый пустой. Файлы ни здесь, ни у пира **не удаляются**; после этого содержимое папки встретится с содержимым пира как новое (возможны conflict-копии).
- `rebind` — считать текущую папку той же самой: индекс сохраняется, и при следующем скане всё, чего нет в папке, будет **удалено у пира**. Если папка пуста — у пира удалится всё.
- Ответы: 200 — успех; 409 — токен устарел (состояние изменилось, нужно перечитать /status); 400 — прочие ошибки (текст в теле).

Go-клиент: `(*app.Ctl).ConfirmFolder(token, action string) error`.

UI обязан явно показывать разницу reset/rebind и спрашивать подтверждение. Для `rebind` при `root_empty` — отдельное предупреждение, что у пира удалится всё.
