# Ревью 01-03: локальное управление и клиенты

### 01-03-01 [medium] Предсказуемый сокет в `/tmp` позволяет блокировать запуск демона
- Где: `internal/config/config.go:53-61`, `internal/app/control.go:21-33`
- Сценарий: на Linux с `TMPDIR=/tmp` путь `SHAREDIR_HOME` длиннее 99 байт → `SocketPath` помещает сокет в общий `/tmp` по детерминированному имени из первых 48 бит SHA-256 пути home. Другой локальный пользователь заранее занимает это имя Unix-сокетом. При старте `listenControl` успешно подключается к нему и считает, что sharedir уже запущен; настоящий демон не запускается. Sticky bit `/tmp` не позволяет жертве удалить чужой сокет.
- Доказательство: путь исполнения: `config.SocketPath` выбирает общий каталог и вычислимое имя (`internal/config/config.go:55-61`); `listenControl` считает любой успешный `DialTimeout` признаком уже запущенного демона и возвращает ошибку до `net.Listen` (`internal/app/control.go:21-28`). Идентичность сервера при этом не проверяется. Для воспроизведения достаточно занять рассчитанный путь Unix-сокетом от другого пользователя, затем запустить `sharedir run` с тем же `SHAREDIR_HOME`: демон завершится с сообщением «уже запущен».
- Исправление: размещать сокет в каталоге с правами только владельца (создать приватный каталог в `TMPDIR` с проверкой владельца/прав) или использовать безопасную per-user runtime-директорию; дополнительно проверять реальный управляющий HTTP-ответ, а не сам факт успешного connect. Задеты `internal/config/config.go`, `internal/app/control.go`.
- Уровень исправления: L2

### 01-03-02 [medium] Файлы автозапуска генерируются без экранирования путей
- Где: `internal/app/service.go:57-79`, `internal/app/service.go:89-110`
- Сценарий: путь бинарника или `SHAREDIR_HOME` содержит специальные символы либо пробелы → LaunchAgent XML получает неэкранированные значения и может стать некорректным (например, `&` в имени каталога); в systemd `ExecStart=%s run` путь с пробелом разбирается как несколько слов, поэтому исполняемый файл не находится. Unit-файл с переводом строки в подставленном пути также может быть разобран как дополнительные директивы.
- Доказательство: значения `exe` и `home` напрямую вставляются в XML-элементы `<string>` (`internal/app/service.go:61-75`), а в systemd-директивы без XML/юнит-экранирования (`internal/app/service.go:94-107`). Запуск сервиса создаётся именно этими файлами через `launchctl bootstrap` и `systemctl enable --now` (`internal/app/service.go:80-83`, `112-116`); поэтому указанные допустимые пути ломают автозапуск.
- Исправление: сериализовать plist через XML encoder/plist-библиотеку; для systemd корректно экранировать аргумент `ExecStart` согласно синтаксису unit-файлов и значения `Environment`, либо явно отклонять пути, которые нельзя безопасно представить. Задет `internal/app/service.go`.
- Уровень исправления: L1
