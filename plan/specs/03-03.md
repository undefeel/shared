# 03-03 Потоковое чтение индекса пира

## Target
Проект sharedir: двусторонняя синхронизация папки между macOS и Linux. Go-демон (`cmd/sharedir`, `internal/*`). Обнаружение — UDP (22101), передача — HTTP поверх взаимного TLS 1.3 (22100), relay через свой VPS. Подробности — `README.md`.

`internal/transport/transport.go`, `Client.Index`: тело ответа читается целиком `io.ReadAll(io.LimitReader(body, limit+1))` (до `MaxIndexBytes` = 512 MiB), затем `json.Unmarshal`. Пиковая память — сырое тело плюс разобранные структуры, то есть почти вдвое больше индекса.

## Change
1. Разбирай ответ потоково: `json.Decoder` поверх считающего ридера с лимитом, который возвращает ошибку «index exceeds size limit» при превышении (а не тихо обрезает). Сырое тело целиком в память не копируется.
2. Записи `files` проверяй по мере чтения (`Token`/`More` для массива): длина имени > 4096 или вектор > 64 записей → ошибка сразу, без дочитывания остального.
3. Формат ответа `/index` и поведение для корректных ответов не меняются; ошибки (превышение размера, битый JSON, слишком длинное имя) возвращаются как раньше — вызывающий код (`internal/app/daemon.go`) не трогай.
4. Idle-таймаут тела (`progressBody`) должен продолжать работать.

## Constraints
- Приёмка шире пакета: `go vet ./... && GOOS=linux go vet ./...`, `go test -race ./...`, `make build`. Ненулевой выход = провал.
- Меняешь лимит или правило — найди grep'ом упоминания в `README.md` и комментариях и обнови.
- Тест не строже условия: корректное альтернативное решение должно проходить.
- Перечисли в теле коммита учтённые конкурирующие пути. Коммить в свою ветку, сообщение начинается с ID задачи.
- Бюджет ~250 строк diff. Не укладываешься или нужен файл вне Ownership — спроси координатора (`orca orchestration ask`).
- Тесты в `internal/transport/transport_test.go`: корректный индекс на 10 000 записей разбирается одинаково со старой реализацией; тело больше лимита → ошибка превышения; длинное имя в середине массива → ошибка; битый JSON → ошибка; тест на память: индекс заметного размера (например 20 MiB) разбирается, и `testing.AllocsPerRun` или `runtime.MemStats` показывает, что сырое тело целиком не копировалось (порог задай с запасом, чтобы тест не был хрупким).
