## Pipeline data flow

Maintain peer epoch/cursor in queue for a runner lifetime, never reset due to body/connection/address failure. Poll only when q.canPoll; process due bounded work first. q.accept retains fetched work, applied cursor advances only once all records for it succeeded. During pending retry do not re-fetch full index. If overflow requires continuation, retain only bounded work and sufficient compact bookkeeping and replay same cursor until all work accepted; no silent drop. Per-record success callback q.applied even for no-op/ignored records, failure q.failed. Version-changed triggers IndexSince exact name, updates pending version; never since=0. Avoid allowing named refresh to replace whole-index completion tracking (add dedicated queue replacement method if needed). Sleep context-aware until retry due (short capped polling acceptable); avoid 50s long-poll starving pending retries. New epoch/reset is baseline boundary. Good batch frames remain usable despite partial stream errors.

Partition due small LIVE records (<=256 KiB each, <=64 and <=8 MiB total) into batches. No batching deletes, no-op local matches, or oversized files unnecessarily. Batch request/responses must be under pool stream and staging accounting; adapter supplies verified []byte bodies to folder staging with reservations retained until apply ends. Singles use existing client.Fetcher (relay gzip already implemented). Do not buffer entire index bodies. Inspect FetchFiles retry semantics; use bounded cancellation/attempt helper if its unbounded stream retry would hold successful frames indefinitely. Both batch and single paths must actually run in tests; do not bypass pool on batches.
