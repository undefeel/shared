# 02-04 Сетевой сервер и клиент: отзыв доступа, таймауты, лимиты

## Target
Проект sharedir: двусторонняя синхронизация одной папки между macOS и Linux. Go-демон (`cmd/sharedir`, `internal/*`), меню-бар macOS на SwiftUI (`macos/SharedirBar`), виджет Omarchy на QML (`omarchy/sharedir`). Обнаружение — UDP-броадкаст (22101), передача — HTTP поверх взаимного TLS 1.3 (22100), ID устройства = SHA-256 сертификата, подключаться может только сопряжённое устройство. Есть relay через свой VPS (`internal/relay`). Подробности — `README.md`, отчёты ревью — `plan/reviews/`.

Сетевой слой: `internal/transport/transport.go` (TLS-конфиги, HTTP-сервер `/index` и `/file`, клиент `Index`/`Fetcher`) и запуск сервера в `internal/app/daemon.go` (около строк 170–185, функции `isPeer`, `rejected`, `Unpair`, `syncPeers`, `Reload`). Находки 01-01-01, 01-01-02, 01-01-03 (часть про `incoming`), 01-01-04, 01-01-05 из `plan/reviews/01-01.md`.

## Change
1. **01-01-01 — отзыв доступа.** Сейчас сопряжение проверяется только в `VerifyPeerCertificate` при handshake. Нужно:
   - в `transport.Server.Handler` на каждый запрос заново проверять, что ID из `r.TLS.PeerCertificates[0]` всё ещё сопряжён (через новый callback `Allowed func(id string) bool`); иначе 403 и закрыть соединение;
   - учитывать входящие соединения по ID пира (через `http.Server.ConnState` или обёртку listener) и при `Unpair`/`Reload`, удаливших пира, закрывать все его соединения — в том числе идущую загрузку и long-poll `/index`, и пришедшие через relay;
   - long-poll `/index`: после ожидания перед ответом проверять разрешение ещё раз.
2. **01-01-02 — таймауты и лимит соединений.** У `http.Server` задай `ReadHeaderTimeout` (он же ограничивает handshake — проверь, что это так в текущей версии Go; если нет — задай deadline на соединение до конца handshake в обёртке listener) и `IdleTimeout`. Ограничь число одновременно принятых соединений (обёртка listener с семафором, общий лимит и лимит на IP для TCP). `WriteTimeout` не ставь глобально: он оборвёт большие файлы и long-poll; вместо этого — idle/progress deadline на запись в `/file`. Входящие relay-каналы тоже под общим лимитом.
3. **01-01-03 (daemon)** — таблица `incoming` (кандидаты, которых `rejected` добавляет при каждом новом отпечатке) получает лимит размера и TTL, как в discovery.
4. **01-01-04 — лимит индекса.** `Client.Index` читает ответ через `io.LimitReader` с обнаружением превышения (ошибка, а не обрезанный JSON). Лимит — константа, достаточная для 1 млн файлов. Длина имени не больше 4096 байт, вектор версии не больше 64 записей — иначе вся запись отклоняется с ошибкой в лог.
5. **01-01-05 — лимит загрузки.** `Fetcher` отклоняет `fi.Size < 0`, копирует не больше `fi.Size+1` байт и возвращает ошибку, если тело длиннее или короче заявленного. У клиента задай `ResponseHeaderTimeout` и idle-таймаут прогресса тела: если байты не приходят дольше N секунд — запрос отменяется (через `context` и таймер, сбрасываемый при каждом чтении). Long-poll `/index` должен продолжать работать: его таймаут ответа больше времени long-poll.

## Constraints
- Приёмка шире пакета: `go vet ./...` и `go test -race ./...` по всему проекту, плюс `make build`.
- Меняешь лимит, таймаут или правило — найди grep'ом все упоминания в `README.md` и комментариях и обнови.
- Проверка в тестах не строже условия: правильное альтернативное решение (другое имя функции, другой порядок проверок) должно проходить.
- Перечисли в комментарии к PR-коммиту все конкурирующие пути, которые учтены. Блокировки — на сущность, а не глобальные. Временная ошибка не должна удалять данные.
- Коммить в свою ветку; сообщение коммита начинай с ID задачи.
- Протокол между устройствами (`/index`, `/file`, заголовки) не меняй — старые пиры должны работать.
- `internal/folder/` не трогай: проект folder параллельно делает задача 02-01. Сигнатуру `folder.Fetcher` не меняй.
- Тесты (в пакете transport тестов пока нет — создай `internal/transport/transport_test.go`): Unpair во время открытого keep-alive соединения → следующий запрос 403, идущая загрузка обрывается; соединение без ClientHello закрывается по таймауту; превышение лимита соединений; индекс больше лимита → ошибка; тело `/file` длиннее и короче `fi.Size` → ошибка; зависшее тело → ошибка по idle-таймауту. Время и таймауты в тестах — короткие через поля/опции, не через Sleep на десятки секунд.

## Ownership
`internal/transport/transport.go`, `internal/transport/transport_test.go`, `internal/app/daemon.go` (только сетевой сервер, `isPeer`, `rejected`, `incoming`, `Unpair`, `syncPeers`, `Reload`, `relayLoop`), `internal/app/relay.go` при необходимости, упоминания таймаутов в `README.md`.
