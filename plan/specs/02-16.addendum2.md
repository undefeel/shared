# 02-16 — доработка по ревью

1. [major] Если `openRootFS(f.Root)` в Scan падает после успешного guardRoot — сейчас возвращается сырая ошибка без latch. Проще и надёжнее: не открывай корень по пути заново, а обходи дерево от удерживаемого root fd из 02-15 (новый поток каталога через `openat(rootfd, ".")`, как делает `rootFS.openDir(".")`). Любая ошибка доступа к корню — через API блокировки (`root_unavailable`). Регрессионный тест: корень исчезает между guard и обходом (инъекция через scanIO.openDir для ".") → папка blocked, индекс на диске прежний.
2. [major] Решение «пустой кандидат при непустом индексе» принимай внутри `commitScan` под `saveMu` и `mu` (по тому же снимку `f.files`, из которого строится `next`), а не до него. Тест: индекс меняется между обходом и commit (хук) → решение принимается по актуальному индексу.
Коммит отдельный, начинается с `02-16`. Приёмка прежняя. Сдай через worker_done.
