# 02-02 Лимиты и гонка accept в relay-сервере

## Target
Проект sharedir: двусторонняя синхронизация одной папки между macOS и Linux. Go-демон (`cmd/sharedir`, `internal/*`), меню-бар macOS на SwiftUI (`macos/SharedirBar`), виджет Omarchy на QML (`omarchy/sharedir`). Обнаружение — UDP-броадкаст (22101), передача — HTTP поверх взаимного TLS 1.3 (22100), ID устройства = SHA-256 сертификата, подключаться может только сопряжённое устройство. Есть relay через свой VPS (`internal/relay`). Подробности — `README.md`, отчёты ревью — `plan/reviews/`.

Relay-сервер: `internal/relay/server.go`, тесты в `internal/relay/relay_test.go`, unit `deploy/sharedir-relay.service`. Находки 01-01-06 и 01-01-07 из `plan/reviews/01-01.md`.

## Change
1. **01-01-06 — лимиты после авторизации.** Сейчас `maxPreAuth` и `maxPreAuthPerIP` действуют только до `leavePreAuth`. Добавь:
   - глобальный лимит активных listen-регистраций (`listeners`) и лимит на один IP;
   - глобальный лимит активных туннелей (pipe) и лимит на один ID отправителя; счётчик уменьшается только когда pipe фактически закрыт;
   - idle-таймаут туннеля: если в обе стороны нет данных дольше N минут, туннель закрывается. Значение — константа, рядом с остальными.
   - Значения выбери разумными для личного relay (десятки устройств) и вынеси в константы в начале файла.
2. **01-01-07 — гонка accept/timeout.** Переход pending → accepted/expired должен быть атомарным (под тем же mutex или через однократный CAS-флаг в pending). Сокет получает только выигравший connect. Если connect уже вышел по таймауту, поздний accept закрывает свой сокет и отвечает клиенту ошибкой. Если сокет уже лежит в канале, а connect выходит по таймауту — сокет из канала забирается и закрывается.
3. **Systemd второй рубеж**: в `deploy/sharedir-relay.service` добавь `MemoryMax=`, `TasksMax=` и уменьши `LimitNOFILE` до значения, согласованного с лимитами из п.1 (с запасом).

## Constraints
- Приёмка шире пакета: `go vet ./...` и `go test -race ./...` по всему проекту, плюс `make build`.
- Меняешь лимит, таймаут или правило — найди grep'ом все упоминания в `README.md` и комментариях и обнови.
- Проверка в тестах не строже условия: правильное альтернативное решение (другое имя функции, другой порядок проверок) должно проходить.
- Перечисли в комментарии к PR-коммиту все конкурирующие пути, которые учтены. Блокировки — на сущность, а не глобальные. Временная ошибка не должна удалять данные.
- Коммить в свою ветку; сообщение коммита начинай с ID задачи.
- Протокол relay (формат кадров, порядок hello/listen/connect/accept) не меняй: старые клиенты должны работать.
- Тест гонки 01-01-07 должен быть детерминированным: управляемое время или хук/барьер в коде (допустим неэкспортируемый хук для тестов), не `time.Sleep` наугад. Прогоняй `go test -race -count=20 ./internal/relay/`.
- Тест лимитов: превышение глобального и per-ID лимита туннелей отклоняется, после закрытия туннеля слот освобождается.
