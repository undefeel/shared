# 02-28 Omarchy виджет

## Target
Проект sharedir: двусторонняя синхронизация одной папки между macOS и Linux. Go-демон (`cmd/sharedir`, `internal/*`), меню-бар macOS на SwiftUI (`macos/SharedirBar`), виджет Omarchy на QML (`omarchy/sharedir`). Ядро синхронизации — `internal/folder/`. Идёт исправление ядра по проекту `plan/design/folder.md` (прочитай целиком: разделы «Решение владельца», «Решения и инварианты», «Совместимость и миграция», «Конкурирующие пути» обязательны для всех задач). Исходные находки — `plan/reviews/01-02.md`.

Уровень L2. Задача из раздела «Задачи реализации» проекта, блок `### 02-28`:

> Цель: folder_error, подтверждение через CLI, сообщения результата. Файлы: `omarchy/sharedir/Service.qml`, `omarchy/sharedir/Widget.qml`, `omarchy/sharedir/Strings.js`. Зависимости: 02-26. Проверки: fixtures старого/blocked status, два действия с подтверждением, stale token/failed CLI остаются ошибкой, отображение при running=true, переключатель resume не снимает root block; ручной QML smoke.

## Change
Реализуй задачу 02-28 точно по блоку выше и по соответствующим разделам «Решения и инварианты» проекта. Зависимости уже влиты в `main`: используй их API, не дублируй. Тесты из блока обязательны — каждый сценарий отдельным тестом.

## Constraints
- Бюджет: до ~300 строк diff и только файлы из Ownership. Если не укладываешься или нужен ещё файл — не расширяй сам: спроси координатора (`orca orchestration ask`) и жди ответа.
- Протокол между устройствами (`/index`, `/file`, формат FileInfo) не меняй. Новых внешних зависимостей не добавляй (`golang.org/x/sys`, `golang.org/x/text` уже есть).
- Архитектуру (Go-демон, JSON-индекс, HTTP поверх mTLS) не меняй. Если проект в чём-то неисполним — спроси координатора, не импровизируй.
- Коммить в свою ветку, сообщение коммита начинается с ID задачи.
- Приёмка шире пакета: `go vet ./...`, `go test -race ./...` по всему проекту, `make build` (включает кросс-сборку под Linux), `GOOS=linux go vet ./...`.
- Тесты пиши под macOS (на этой машине они запускаются). Linux-специфичные тесты помечай build-тегом `linux` и убедись, что они компилируются: `GOOS=linux go test -c -o /dev/null ./internal/folder/`. Их запуск на Linux делает владелец отдельно.
- Меняешь правило, лимит или формат — найди grep'ом все упоминания в комментариях и `README.md` и обнови (README целиком переписывает отдельная задача 02-29; здесь — только явно устаревшие места).
- Проверки в тестах не строже условия: корректное альтернативное решение должно проходить.
- Перечисли в теле коммита все конкурирующие пути, которые учтены. Блокировки — в порядке из проекта (scanMu → saveMu → mu). Временная ошибка ввода-вывода никогда не превращается в удаление или tombstone.
- Fault injection — через небольшие внутренние интерфейсы или неэкспортируемые хуки, не через chmod под root.
- Swift: соберись `make app`. QML: синтаксис проверь `qmllint`, если доступен; иначе опиши ручной smoke в отчёте.
- Тексты интерфейса на русском и английском, коротко и понятно обычному пользователю.
