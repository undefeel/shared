## Data flow and APIs

1. `clone.go`: fd-only bounded copying and platform clone wrapper. Suggested signatures `cloneInto(src,dst *os.File,size int64) error` and platform `platformClone(src,dst *os.File) error`. Existing exclusive rooted tmp creation supplies independent destination inode. Linux use unix.IoctlFileClone (FICLONE). Darwin x/sys safe fd API may not support cloning into existing fd: use Fclonefileat into exclusively named leaf at held parent, or safely fall back to copy if no safe API available; never absolute paths. For platform unsupported, EXDEV, ENOTSUP/EOPNOTSUPP, ENOSYS (and documented filesystem unsupported EINVAL) copy from held source fd, resetting/truncating destination if necessary. Return all other errors. Copy at most expected size plus detection of extra bytes, context if practical, no unbounded allocation. No hardlinks. Hash verify resulting tmp before acceptance. Use injectable function parameters in internal helpers for deterministic fallback/error tests, not global mutable hooks.
2. `reuse.go`: candidate snapshot helper `reuseCandidates(fi FileInfo) []FileInfo`, `hasReusableContent(fi FileInfo) bool`, staging `downloadOrReuse(ctx,fi,fetch) (string,error)`. Keep in-memory hash->live canonical names on Folder, guarded by mu. In index.go add field, initialize after load, and rebuild in notify (all publication paths already notify under mu). Candidate lookup copies names and current FileInfos under mu, opens rooted descriptors and calls stableHash OUTSIDE all locks. Prefer target first. Check hash AND size; Exec is independent and must never prevent reuse. Validate canonical/Disk pairs. Stale candidate/error during validation must fall back to normal fetch, without index mutation/deletes. Real clone/copy I/O errors other than unsupported/cross-device must propagate. Verify source stat stability across clone/copy and resulting hash; changing candidate discards tmp and falls back to fetch.
3. `apply_stage.go`: replace download with downloadOrReuse. Existing prepareApply requires tmp for st.needsDownload even if target has bytes: cloning target to tmp is acceptable and preserves durable Vector/Exec transitions; no shortcut that skips group commit. For Exec-only same-hash path existing local fd provides bytes.
4. Important: app pipeline prefetches /files based on NeedsRemoteContent BEFORE staging. In apply.go make only a tiny reuse hook in NeedsRemoteContent so verified reusable local content returns false; no other planning/ignore edits. It is only a hint; revalidate at staging, falling back to singleton fetch if changed. Do not modify peer pipeline.
5. Important: prepareApply currently copies staged/local source into a SECOND incoming inode under scanMu. Replace that single io.Copy call with cloneInto helper (bounded by remote size), preserving surrounding metadata, capture, permissions, errors, no-replace and G1. This prevents discarding the CoW advantage. If Darwin clone requires absent leaf, adapt helper to held parent/new unique destination creation at the existing incoming creation call site; no new unsafe pathname operations. Do not hash under scanMu in new code: staging verifies bytes, existing post-capture hash is deliberate. Ensure final prepared incoming still verified using existing checks; inspect them.
