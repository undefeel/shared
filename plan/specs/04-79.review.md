# 04-79 performance report

## Method and attribution

macOS arm64, Apple M4. Baseline profiles: `SHAREDIR_PERF=1 go test -run Perf -count=1 -cpuprofile /tmp/0479.cpu -blockprofile /tmp/0479.block -mutexprofile /tmp/0479.mutex ./internal/app/`. Post-change profiles used the same command and `/tmp/0479.after.{cpu,block,mutex}`. CPU samples and summed goroutine delays cover the whole harness, including setup, cleanup and reuse; they are not a breakdown of timed first sync. Post-change profiles overlapped an unrelated folder test, so comparisons are indicative, not controlled attribution.

The profiles include concurrent waits and cannot be added into elapsed time. Stability preflight intentionally performs two observations separated by the default second; test helper changes were not applied globally because this would change stability integration coverage and tests use synchronization deadlines. Verified incoming inode evidence was not seeded: proving invalidation against external changes exceeds the cheap, safe optimization in this task. Rooted directory operations and required inode/group/directory durability remain; no numeric first-sync attribution to individual mandatory calls is claimed.

## Changes

Builtins use exact/prefix/suffix component checks over the same cleaned ancestor chain; user rules still use the original path.Match matcher, including malformed patterns. No combined builtins/user allocation is made. Scalar epoch/cursor reads use DurableCursor under scanMu → saveMu → mu, including the store replacement fence; DurableState retains detached deep-copy semantics. The Hello and WaitDurable scalar-only paths use the getter. Reference equivalence tests cover each built-in, ancestors, near misses, dot paths and user/malformed globs; the snapshot test compares epoch/cursor with the detached state. No product stability, exclusions, reuse, own-event, flush, recovery or transport guarantee changes.

In-process matching benchmark (ns/op, B/op, allocs/op): reference 4339, 1280, 2; optimized 331.1, 0, 0. It tests matching without filesystem work and is not a first-sync timing.

## Documentation

No rule or numerical guarantee changed. Inspection of README.md, docs/ and plan/design/perf.md found pre-existing stale text: README.md:168 names index.json; perf.md R20 and R3 body retain the older per-file FULLFSYNC formulation, overridden by owner decisions at the top. Documentation is owned by 04-78.

The built-in patterns are represented both in `builtinIgnore` and in the fast matcher; adding or changing a built-in requires updating both. The per-rule reference equivalence test is intended to catch that drift. `TestDurableCursorMatchesSnapshot` compares both fields before and after a scan; the accessor uses the same lock fence as DurableState, including around rebind's store replacement. Existing WaitDurable and app peer-state tests exercise the changed callers.

At the coordinator's direction a final five-trial run was made without other worktree tests scheduled by the coordinator, but a separate host `go test -race ./...` (app, folder, transport) overlapped it. The five n=2092 values were 2.45501, 2.41651, 2.46936, 2.42963 and 2.44846 s; median 2.44846 s, fsync=2648, FULLFSYNC=99, G=33, index 149354–149927 bytes, intent 823550–823848 bytes. It is not an isolated comparison or proof of the 2.3 s target; independent repetition under comparable host load remains necessary. A preceding run with an overlapping TestDeltaServer had median 2.25755 s and is likewise excluded from conclusions. These observed medians are below baseline but do not establish a controlled improvement.

## Verification

`go vet ./...`, `GOOS=linux go vet ./...`, `go test -race ./...` (folder 149.2 s, app 75.9 s), Linux compilation of folder/app/transport tests and `make build` passed. The race suite exercises the folder/app tests, including ignore, stability, reuse, scan staging/incremental, own-event, Hello and canceled durable wait. The post-change perf harness completed successfully; raw logs and profiles are under `/tmp/0479*`. As observed in the whole-harness block profile, stability preflight contributes 18.03 s summed before and 18.02 s after, but these concurrent waits include setup and cannot establish wall-clock suite inflation. Its one-second production interval is intentional, and no general test fixture interval was changed because some tests exercise stability and synchronization.
