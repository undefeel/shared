## Lead workflow (mandatory — you are the LEAD, not the implementer)
Smart model plans, light model implements, smart model reviews. The coordinator does not take part.
1. Plan (cheap, most important): read this spec and the design, then write `plan/specs/04-72.plan.md` — files and functions to add/change, signatures, data flow, invariants and lock order, exact test list with scenarios, and pitfalls. Precise enough that a weaker model cannot go in the wrong direction. Commit it.
2. Delegate: run `plan/tools/lead.sh 04-72 implement`, or, if the plan splits into parts with disjoint files, up to 3 parallel parts (`plan/tools/lead.sh 04-72 part <name> <part.md>` each, then `plan/tools/lead.sh --wait-all <dispatches>`; parts do not commit — you run the full acceptance and commit). A large plan may also be delivered as sequential phases (one `implement` per committed phase plan, at most 3). A luna worker implements the plan in this worktree, runs acceptance, commits and reports. Exit code 3: answer its question (`orca orchestration reply --id <id> --body ...`) if it asked one, then re-run `plan/tools/lead.sh --wait <dispatch>`.
3. Review: run the acceptance commands yourself, then the cheap first pass `plan/tools/self-review.sh 04-72` (Gemini), then review the whole diff yourself (correctness, races, durability, plan conformance, tests really testing the claims). Reject Gemini findings that contradict the spec or the owner decisions.
4. Fix rounds: if changes are needed, write the notes to a file under `$(git rev-parse --git-dir)/` and run `plan/tools/lead.sh 04-72 fix <N> <file>` (N = 1, then 2). At most 2 fix rounds.
5. Never end your turn while a child worker (implementer or reviewer) is running: Orca does not wake you when it reports. On exit code 3 immediately re-run the `--wait` command.
6. Takeover: if after 2 fix rounds the review still does not pass, finish the task yourself (that is the safety net against endless iterations).
7. worker_done: plan file, number of implementer/fix rounds, whether you took over, every finding (Gemini and yours) with its disposition, acceptance results.

Extra rules for this task (learned on 04-60…04-71: luna repeatedly gave up on whole plans):
- Give the implementer small pieces: parts or sequential phases of at most ~300 lines each, every piece naming exact files, functions, signatures and tests. Prefer 2–3 pieces over one big `implement`.
- Takeover is mandatory and complete: after the fix rounds you finish everything that is missing yourself. Sending worker_done with outcome failed is acceptable only for a concrete technical blocker you name; "not finished" is not a blocker.
