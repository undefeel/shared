# 02-01 Проект исправлений ядра синхронизации (folder)

## Target
Проект sharedir: двусторонняя синхронизация одной папки между macOS и Linux. Go-демон (`cmd/sharedir`, `internal/*`), меню-бар macOS на SwiftUI (`macos/SharedirBar`), виджет Omarchy на QML (`omarchy/sharedir`). Обнаружение — UDP-броадкаст (22101), передача — HTTP поверх взаимного TLS 1.3 (22100), ID устройства = SHA-256 сертификата, подключаться может только сопряжённое устройство. Есть relay через свой VPS (`internal/relay`). Подробности — `README.md`, отчёты ревью — `plan/reviews/`.

Ревью нашло в ядре синхронизации (`internal/folder/`, `internal/app/daemon.go`) связанные проблемы. Полное описание — `plan/reviews/01-02.md`, сводка — `plan/reviews/SUMMARY.md`. Тебе нужно спроектировать их исправление и разбить его на задачи для исполнителей. Код не пишешь.

## Change
Создай `plan/design/folder.md` — технический проект исправлений для находок:
- 01-02-01 запись и удаление через локальный симлинк вне корня (операции относительно дескриптора корня, без выхода через ссылки, macOS и Linux);
- 01-02-02 неполный обход подкаталога не должен публиковать удаления;
- 01-02-03 пропавший или подменённый корень (отмонтирован, путь в конфиге сменён, корень — симлинк);
- 01-02-04 повторная проверка решения под блокировкой после загрузки, защита от потери локальной записи;
- 01-02-05 сериализация `save()`, неизменяемый снимок под mu, уникальные tmp, гонка с mergeOnly;
- 01-02-06 уникальные имена conflict-файлов без перезаписи;
- 01-02-07 коллизии NFC/NFD, требование канонических входящих имён;
- 01-02-08 порядок долговечной фиксации (fsync файла, каталога, индекса);
- 01-02-09, 01-02-10 права и исполняемый бит;
- 01-02-11 со стороны folder: отрицательный и заявленный размер (лимит потока в transport делает отдельная задача 02-04: `Fetcher` копирует не больше `fi.Size+1` байт и возвращает ошибку при превышении, плюс idle-таймаут).

Решения владельца проекта (обязательны, не пересматривай):
1. Корень пропал или пуст при непустом индексе → синхронизация этой папки останавливается, демон публикует ошибку в `Status`, меню macOS и виджет Omarchy её показывают. Возобновление — только после явного подтверждения пользователя (новая команда control-канала и пункт меню), которое сбрасывает индекс или привязывает его к новому корню.
2. Права: у существующего файла сохраняются его локальные права (0600 остаётся 0600). Новые файлы создаются 0644 или 0755. Между машинами синхронизируется только исполняемый бит, и его изменение — это изменение версии файла.
3. Правка против удаления: правка побеждает, удалённый файл возвращается. Это фиксируется в README.

В проекте должны быть:
- **Решения** по каждой находке: что меняется, какие инварианты, почему так. Для 01-02-01 — конкретный механизм на macOS и Linux (например, `openat`/`O_NOFOLLOW`, `renameat`, `unlinkat` через `golang.org/x/sys/unix` или `os.Root` из Go 1.24+ — проверь версию Go в `go.mod`). Добавлять новые внешние зависимости кроме `golang.org/x/sys` нельзя.
- **Совместимость**: формат `index.json` и протокол `/index`, `/file` у старых пиров. Если формат меняется — миграция при загрузке.
- **Конкурирующие пути**: watcher, Scan, несколько runPeer, локальные процессы, рестарт и сбой питания.
- **Разбиение на задачи** реализации. Для каждой: ID (02-10, 02-11, …), цель, точный список файлов, зависимости, уровень L1–L3, тесты, которые она добавляет (с конкретными сценариями: симлинк наружу, EACCES подкаталога, пустой корень, параллельный save, коллизия conflict-имени, NFD-имя). Ограничения: в задаче не больше 5 файлов и примерно 300 строк diff. Задачи, которые можно делать параллельно, не трогают одни и те же файлы. `internal/app/daemon.go` и `internal/transport/transport.go` сейчас правит задача 02-04 — задачи, которым нужны эти файлы, ставь в зависимость от «02-04». Отдельной задачей L1 — правка `README.md` (политика правка против удаления, остановка при пропавшем корне, права).
- **Риски и открытые вопросы**, которые требуют решения владельца.

## Constraints

- Читать можно весь репозиторий. Можно писать временные эксперименты (например, проверить поведение `os.Root` с симлинком), но перед коммитом удали их.

- Архитектуру и стек проекта (Go-демон, HTTP поверх mTLS, JSON-индекс) не меняй. Если без этого никак — опиши в «Открытых вопросах», не закладывай в задачи.
