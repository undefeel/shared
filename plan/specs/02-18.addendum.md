# 02-18 — дополнение координатора (по итогам 02-17)

После ревью 02-17 `discard` удаляет recovery-копию только если она указывает на захваченный inode (сверка dev/ino), а объект, восстановленный через `openCapture` без identity, в discard отказывает. Поэтому:
- intent хранит dev и ino захваченного inode рядом с именем capture;
- при recovery «индекс уже зафиксирован» capture открывается с этой identity и удаляется через обычный `discard`; если identity не совпала — файл не удаляется, а сохраняется как видимый conflict, папка не блокируется;
- Ownership дополнительно: `internal/folder/capture.go` — только чтобы `openCapture` принимал сохранённую identity.
Тест: crash после commit индекса до discard → recovery удаляет capture; тот же сценарий, но recovery-имя подменено другим файлом → файл сохранён как conflict.
