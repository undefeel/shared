# 03-02 Отдельный лимит для каналов через relay

## Target
Проект sharedir: двусторонняя синхронизация папки между macOS и Linux. Go-демон (`cmd/sharedir`, `internal/*`). Обнаружение — UDP (22101), передача — HTTP поверх взаимного TLS 1.3 (22100), relay через свой VPS. Подробности — `README.md`.

`internal/transport/transport.go`: `Connections.Limit(listener)` ограничивает принятые соединения общим лимитом (128) и лимитом на IP (16). Демон (`internal/app/daemon.go`, около `srv.Serve(tls.NewListener(d.connections.Limit(relayLn) …`) оборачивает тем же лимитом и listener каналов через relay. Все relay-каналы приходят с одного адреса — IP VPS (если RemoteAddr у них tcp), поэтому «16 на IP» на деле ограничивает все relay-соединения всех пиров разом.

## Change
1. Дай `Connections` способ обернуть listener **без** лимита на IP, но со своим отдельным лимитом (например `LimitRelay(l net.Listener, max int)` или опция). Для relay-listener: лимит на IP не применяется; действует отдельный счётчик relay-каналов (по умолчанию 64) и общий лимит 128 остаётся общим для прямых и relay.
2. В `daemon.go` замени обёртку relay-listener на новую — одна строка.
3. Прямые TCP-соединения ведут себя как раньше.

## Constraints
- Приёмка шире пакета: `go vet ./... && GOOS=linux go vet ./...`, `go test -race ./...`, `make build`. Ненулевой выход = провал.
- Меняешь лимит или правило — найди grep'ом упоминания в `README.md` и комментариях и обнови.
- Тест не строже условия: корректное альтернативное решение должно проходить.
- Перечисли в теле коммита учтённые конкурирующие пути. Коммить в свою ветку, сообщение начинается с ID задачи.
- Бюджет ~250 строк diff. Не укладываешься или нужен файл вне Ownership — спроси координатора (`orca orchestration ask`).
- Тесты в `internal/transport/transport_test.go`: 20 relay-каналов с одинаковым RemoteAddr принимаются (раньше обрезались на 16); превышение relay-лимита отклоняется; закрытие канала освобождает слот; прямые соединения по-прежнему ограничены 16 на IP; общий лимит считает оба типа.
