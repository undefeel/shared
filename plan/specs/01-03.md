# 01-03 Ревью: локальное управление и клиенты

## Target
Проект sharedir: двусторонняя синхронизация одной папки между macOS и Linux. Go-демон (`cmd/sharedir`, `internal/*`). Обнаружение — UDP-броадкаст в LAN (порт 22101), передача — взаимный TLS 1.3 на 22100, ID устройства = SHA-256 сертификата, подключаться может только явно сопряжённое устройство. Есть relay через свой VPS для связи через интернет. Конфликты: побеждает более поздняя правка, другая сохраняется как `имя.sync-conflict-ДАТА-ВРЕМЯ-УСТРОЙСТВО.ext`. Подробности — `README.md`.

Демон управляется по локальному control-каналу: его используют приложение меню-бара macOS (SwiftUI) и виджет бара Omarchy (QML).

Область ревью (только чтение): `internal/app/control.go`, `internal/app/service.go`, `cmd/sharedir/main.go`, `cmd/sharedir/tray_*.go`, `internal/tray/`, `internal/i18n/`, `macos/SharedirBar/*.swift`, `macos/build.sh`, `macos/Info.plist`, `omarchy/sharedir/` (Service.qml, Widget.qml, Strings.js, manifest.json), `Makefile`.

## Change
Найди уязвимости и баги в локальной поверхности управления и клиентах. Обязательно проверь:
- Control-канал: транспорт (unix-сокет или TCP), права на сокет и его каталог, слушает ли он только localhost, может ли другой локальный пользователь или веб-страница (DNS rebinding, CSRF на localhost-HTTP) управлять демоном или сопрягать устройства, лимиты размера запроса, обработка мусора.
- Установка сервиса (`service.go`): генерация LaunchAgent plist и systemd unit — экранирование путей с пробелами и спецсимволами, права файлов, подстановка в shell.
- CLI `main.go`: обработка аргументов, создание конфига и ключа (права 0600/0700), поведение при повторном `init`.
- macOS: запуск встроенного демона и его остановка, гонки при выходе, разбор ответа control-канала (нет ли падений на неожиданных данных), подтверждение сопряжения со сверкой ID — нельзя ли сопрячь без участия пользователя.
- Omarchy QML: как вызывается демон (`Process`/shell), нет ли подстановки данных от пира (имена устройств, файлов) в командную строку.

## Constraints
- Это ревью: **исходный код не меняй**. Единственный файл, который ты создаёшь и коммитишь, — `plan/reviews/01-03.md`.
- Чтобы подтвердить находку, можно писать временные тесты и запускать их (`go test -race -run … ./internal/…`), но перед коммитом удали их. Код репро-теста вставь в отчёт.
- Включай только то, что подтверждено кодом (конкретный путь исполнения) или запуском. Догадки без пути исполнения — в отдельный раздел «Под вопросом», не больше 5 пунктов.
- Стиль и вкусовщину не пиши. Нужны баги, гонки, потеря данных, уязвимости, неверная обработка ошибок с реальными последствиями.
- Проверь все конкурирующие пути: горутины, повторные подключения, одновременные правки на двух машинах, обрыв посреди передачи, рестарт демона.
- Отчёт — на русском языке.

## Формат отчёта `plan/reviews/01-03.md`
Находки отсортированы по серьёзности. Каждая — отдельный раздел:

```
### 01-03-NN [critical|high|medium|low] Короткое название
- Где: path/to/file.go:LINE (и другие места)
- Сценарий: входные данные / состояние → что происходит не так (конкретно)
- Доказательство: путь исполнения по строкам или репро-тест (код + вывод)
- Исправление: что поменять, какие файлы задеты
- Уровень исправления: L1|L2|L3 (L1 — локально, решение очевидно; L2 — логика в 1–2 модулях; L3 — несколько модулей, конкурентность, протокол)
```

В конце — таблица «ID | серьёзность | файл | уровень» и раздел «Под вопросом».
