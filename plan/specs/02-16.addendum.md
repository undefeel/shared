# 02-16 — дополнение координатора (по ревью 02-15)

`guardRoot` из 02-15 пока нигде не вызывается в production-коде: замена корня на другой каталог после Open проходит через Scan и может записать tombstone по старому индексу. В этой задаче:
- вызывай guard под `scanMu` в начале Scan и **повторно непосредственно перед публикацией кандидата** (внутри commitScan до persist);
- при ошибке guard Scan ничего не публикует и переводит папку в blocked (через API 02-15), а не просто возвращает ошибку;
- тест: после Open корень переименован и на его месте создан новый пустой каталог (или каталог с другими файлами) → Scan не пишет ни одного tombstone, индекс на диске прежний, папка blocked с кодом root_changed.
Apply и выдача /file подключают guard в 02-20 и 02-23 — здесь их не трогай.
