# 03-04 Инструкция: проверка устойчивости к сбою питания

## Target
Проект sharedir синхронизирует папку между двумя машинами. При применении входящего файла демон делает так (подробно — `plan/design/folder.md`, раздел «Снимки и долговечность»): скачивает во временный файл и делает fsync; пишет журнал операции `intent.json` и делает fsync; переносит старую версию файла в служебную recovery-копию; ставит новый файл без перезаписи; делает fsync каталогов; записывает `index.json` и делает fsync; удаляет recovery-копию и `intent.json`. При запуске демон сначала доделывает или откатывает незаконченную операцию по `intent.json`. Автотесты проверяют это убийством процесса (SIGKILL), но не настоящим отключением питания: кэш накопителя так не моделируется.

## Change
Напиши `docs/power-loss-check.md` — пошаговую инструкцию для владельца, как проверить это вручную на виртуальной машине Linux (основной вариант) и, по желанию, на реальном томе macOS. В инструкции:
1. Что нужно: VM с Linux (ext4), собранный `bin/sharedir-linux-amd64`, вторая машина-пир или второй экземпляр демона с другим `SHAREDIR_HOME`.
2. Подготовка: папка с несколькими тысячами файлов, сопряжение, дождаться полной синхронизации.
3. Нагрузка: на пире в цикле менять и создавать файлы (готовый однострочник bash), чтобы на VM всё время шло применение входящих изменений.
4. Сбой: жёсткое выключение VM без shutdown (например, `virsh destroy <vm>` или «Power off» в UTM/VirtualBox) в случайный момент. Повторить 10–20 раз.
5. Проверка после каждого включения:
   - демон запускается; в `sharedir status` либо нормальная работа, либо понятная остановка папки (тогда записать код);
   - в папке нет файлов с префиксом `.sharedir-tmp-` старше нескольких минут, нет `intent.json` в каталоге состояния после полного запуска;
   - после синхронизации хеши всех файлов совпадают с пиром (готовая команда: `find … -type f -print0 | sort -z | xargs -0 sha256sum` на обеих сторонах и `diff`);
   - на пире не появилось неожиданных удалений и conflict-копий без причины.
6. Что считать провалом и что прислать координатору: вывод `sharedir status`, лог демона (`journalctl --user -u sharedir`), список расхождений.
7. Для macOS — коротко: те же шаги на внешнем APFS-диске с выдёргиванием кабеля во время синхронизации (вместо отключения питания всей машины).

## Constraints
- Пиши по-русски, просто, для человека, который знает терминал, но не знает внутренностей sharedir. Без внутренних терминов вроде capture, generation, scanMu. Команды — в блоках кода, проверяемые по смыслу.
- Код проекта не трогай.
- Объём — 1–2 экрана.
