# 02-13 — доработка по ревью и координатору

Ownership расширен: можно менять `internal/folder/index.go` (только для п.1) и добавить `internal/folder/scan_cache.go`, если удобнее.

1. **[major] Порядок commit.** Сейчас `commitScan` публикует `f.files/f.clock` до `save()` и при ошибке откатывает без `saveMu` — параллельный Apply/save может записать несогласованный снимок, а откат затрёт более новое изменение. Сделай так: `commitScan` берёт `saveMu` (порядок scanMu → saveMu → mu), под `mu` строит кандидат и его глубокий снимок, отпускает `mu`, долговечно пишет снимок (вынеси тело записи из `save()` в общую функцию `persistLocked(p persisted)`, вызываемую с удержанным saveMu; `save()` её же использует), и только после успешной записи под `mu` публикует `files/clock/ignore`, затем notify. При ошибке записи ничего не публикуется и отката нет.
2. **Кэш хешей.** Сейчас каждый Scan перечитывает все файлы — на больших папках это неприемлемо. Добавь в `Folder` кэш в памяти (не сохраняется на диск): Disk-путь → (dev, ino, size, mtime ns, ctime ns, mode, hash). Если все поля совпали с текущим `fstatat` — hash берётся из кэша без чтения. Иначе — `stableHash`, и кэш обновляется только после успешного commit. После рестарта первый Scan хеширует всё (это ок). Записи для пропавших путей удаляются при commit.
3. **Мелочь:** в `commitScan` ветка `if old.Size == fi.Size … { Copy } else { Copy }` бессмысленна — убери. Верни лог `скан: локальных изменений: N`.
4. **Тесты сильнее:** в сценариях ошибок (EACCES подкаталога, Info EIO, hash, чтение ignore) сравнивай полный индекс до и после — все поля, включая Version и clock, а не только имя/Deleted. Добавь тест п.1: ошибка persist → индекс в памяти и на диске прежний, параллельный save не теряется. Тест п.2: второй Scan без изменений не открывает файлы на чтение (счётчик через scanIO.openRead); изменение содержимого с восстановленным mtime ловится по ctime.
5. NFC-коллизии здесь не делай — это задача 02-14.
