# 03-01 Discovery не вытесняет сопряжённых пиров

## Target
Проект sharedir: двусторонняя синхронизация папки между macOS и Linux. Go-демон (`cmd/sharedir`, `internal/*`). Обнаружение — UDP (22101), передача — HTTP поверх взаимного TLS 1.3 (22100), relay через свой VPS. Подробности — `README.md`.

`internal/discovery/discovery.go`: таблица `devices` ограничена `maxDevices` (256). При переполнении `removeOldestLocked` удаляет самую старую запись — флуд поддельных UDP-анонсов может вытеснить настоящего сопряжённого пира, и связь с ним уйдёт с прямого адреса на прописанный/relay.

## Change
1. Добавь в `Discovery` необязательный callback `Keep func(id string) bool` (задаётся до начала приёма или через сеттер, потокобезопасно). Записи, для которых `Keep(id)` true, при переполнении **не вытесняются**; вытесняется самая старая из остальных. Если все записи «keep» и места нет — новый неизвестный ID просто не добавляется.
2. Истечение по TTL действует на все записи как раньше (сопряжённый пир, переставший анонсироваться, удаляется по TTL — это нормально).
3. В `internal/app/daemon.go` при старте discovery передай `d.isPeer` как Keep — одна-две строки, больше в daemon.go ничего не меняй.
4. Учти, что `Keep` берёт мьютекс демона: вызывай его **вне** `d.mu` discovery либо убедись, что порядок блокировок не создаёт дедлок (daemon.mu → discovery.mu не должен встречаться в обратном порядке). Опиши решение в коммите.

## Constraints

- Меняешь лимит или правило — найди grep'ом упоминания в `README.md` и комментариях и обнови.
- Тест не строже условия: корректное альтернативное решение должно проходить.
- Перечисли в теле коммита учтённые конкурирующие пути. Коммить в свою ветку, сообщение начинается с ID задачи.
- Бюджет ~250 строк diff. Не укладываешься или нужен файл вне Ownership — спроси координатора (`orca orchestration ask`).
- Тесты в `internal/discovery/discovery_test.go`: таблица заполнена 256 поддельными ID + сопряжённый пир → 10 000 новых анонсов не вытесняют сопряжённого; без Keep поведение прежнее; все записи keep → новый ID не добавляется, ошибок нет.
