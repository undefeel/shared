# 04-50b Bounded log writer — review fixes

## Target
Project sharedir (Go daemon `cmd/sharedir`, `internal/*`). Branch `undefeel/t04-50` (this worktree) already contains commits 9bc73df and 550d440: a rotating log writer `internal/app/loglimit.go` (5 MiB × 3 files on macOS, stderr/journald on Linux). Review found defects that are still present in the code. This task fixes them. Do not revert the existing commits; add new ones.

## Change
Fix every item below and add a test for each item marked (test).
1. [major] A failed rotate() leaves `w.file == nil` and every later Write returns ErrClosed forever. Make rotation failure recoverable: keep or reopen a usable file (e.g. reopen the active path with O_APPEND) and retry rotation on a later write; never disable logging permanently because of a transient error (EMFILE, ENOSPC, rename failure). Test with an injected failure followed by a successful write.
2. [major] Do not `Truncate(0)` an existing oversized log on start: rotate it (it becomes `.1`) instead of destroying history.
3. [major] Do not split one Write call (one log line) across two files: if the line does not fit into the remaining space, rotate first and write the whole line into the new file. A single line larger than the limit may go alone into a file.
4. [major] Add the required test "journald no duplicate file": on Linux (non-darwin) `cmd run` keeps logging to stderr only and creates no log file. Make the decision a small testable function (e.g. `logOutput(goos string, ...)`) so it is testable on macOS too.
5. [minor] Open the new file in rotate() with O_APPEND, same as in NewBoundedLogWriter.
6. [minor] No double Close of `f` when rotate() fails inside NewBoundedLogWriter.
7. [minor] When `sharedir run` is started interactively (stderr is a terminal), also log to stderr; when stderr is not a terminal, log to the file only.
8. [major, found by the coordinator] On macOS the menu bar app (`macos/SharedirBar/Store.swift`, `p.standardError = log`) and the launchd plist (`internal/app/service.go`, `StandardErrorPath`) already point the daemon's stdout/stderr at the same `~/Library/Logs/sharedir.log`, via a non-O_APPEND fd. After rotation those fds keep writing into the renamed file (and panics may overwrite the middle of the file). After opening and after every rotation, on darwin redirect fds 1 and 2 to the current log file with `unix.Dup2` (from `golang.org/x/sys/unix`), unless stderr is a terminal (item 7). Test: after a forced rotation, writing to `os.Stderr` lands in the active file, not in `.1`.

Tests required: (test) for items 1, 2, 3, 8 — injected rotate failure followed by a successful write; oversized existing log is rotated to `.1`, not truncated; a line that does not fit is written whole into the new file; after a forced rotation a write to fd 2 lands in the active file. Item 8's fd test may be darwin-only (`//go:build darwin`).
