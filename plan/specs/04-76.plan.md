## Piece 1: durable membership and exact ACK state (folder)
Files: new internal/folder/peerstate.go and peerstate_test.go; store_codec.go; index.go hooks only.
Extend storeControl additively with sorted member records (peer identity, membership incarnation/baseline status and remote store epoch), exact retired deletion records and sparse causal metadata if needed. Preserve gob compatibility and existing positional storeAck tests (do not add fields to storeAck unless updating those tests is strictly necessary). PeerSetEpoch is durable, changes on explicit member set changes; adding/removing members invalidates prior baseline/ACK authorization. Same IDs after removal/re-add must never reuse prior ACKs. Validate canonical sorted unique nonempty member IDs and retired names/vectors. Deep copy all mutable control slices before mutation.
Public APIs (equivalent signatures acceptable if necessary): SetPeers(ids []string) error; PeerACKState() (localStoreEpoch string, membershipEpoch uint64, members []string); Acknowledge(peer, storeEpoch string, membershipEpoch uint64, deletions []FileInfo, baseline bool) error. Add separate baseline handshake fields/API as required to distinguish remote epoch from target epoch. An ACK identifies exact name + vector; never infer ACK from index reception or a device-wide clock. Accept only current member and current target store/membership epoch; idempotent duplicates do not append. Baseline authorization is a durable handshake for the current incarnation and target checkpoint; no client-supplied boolean alone may authorize unobserved baseline. ACK only when target has that exact tombstone; local outgoing ACK only when local durable record is same deletion or a live edit strictly dominating its vector. Store deletion ID as deterministic hash(name, canonical vector), or equivalently persist exact tuple with collision-free equality. Non-dominating concurrent edit never ACKs.
Mutations lock scanMu -> saveMu -> mu; snapshot under mu, release mu for append; publish only after successful append. No network/hash/walk under scanMu or mu. Use existing durable store frame kinds PeerAck/Control and existing error blocking conventions. ACK/control-only changes must not make full index copies or writes for no-op sync. Restart restores state before network/GC. Rebind/reset fencing must invalidate stale ACKs by store epoch/membership incarnation.
Tests: sparse vector holes cannot be compressed into an unsafe floor; exact version vs neighboring name/vector; duplicate append count unchanged; wrong epoch/member/baseline rejected; restart ACK replay; unpair/re-pair clears previous authorization; append failure never publishes success.

## Piece 2: collector and authenticated wire
Files: new folder/tombstone.go and tombstone_test.go; new transport/ack.go and ack_test.go; transport.go registration only.
CollectTombstones(now time.Time) (int,error): retention is 30*24h from first locally persisted observation, never remote time. Require every current configured member baseline authorized and exact deletion acknowledged. Offline has no timeout. Negative/future/ambiguous interval postpones GC. Preserve first observation only for same exact deletion, restart retention for replacement deletion vector (index.go hook may correct existing persistStore preservation). Group-commit DeletedAt must also be local time: inspect existing path and only change other files if strictly required.
Append a GC frame atomically containing DeleteRecord plus causal retirement before publishing removal. Conservative safe choice: retain exact per-name retired vectors indefinitely as sparse exceptions, never advance a global floor across holes. GC need not save memory before safe compression. Prevent old index entries from resurrecting after GC: add smallest necessary hook in apply decision path to ignore vectors dominated by retired exact version; do not suppress newer/concurrent edits. Legacy/retired remote store epoch requires full bootstrap; stale indexes cannot be turned into new local edits. GC changes must wake index cursors/reset baseline through existing mechanisms, and not touch user filesystem.
ACK v2 POST /ack uses existing certified TLS session/version checks; derive sender from certificate and check current allowed callback, never body peer ID. Bound body, count, vectors; reject malformed/unknown fields/trailing JSON and wrong epoch, report persistence failures non-2xx. Client Ack(ctx,addr,peerID,msg) error uses existing v2 authenticated session. Payload carries target store epoch, target membership epoch, exact deletion records and baseline checkpoint evidence. Keep registration field/API changes small. Handle duplicate ACK.
Tests: 30-day offline no GC, both ACK + retention GC, rollback no GC, GC replay/compaction no resurrection with stale remote entry, changed deletion retention reset, exact deletion only, no unauthenticated/mis-certified ACK, wrong epoch, bounded malformed body, append failure.

## Piece 3: daemon wiring and integration
Files: daemon.go wiring only; new app/ack_integration_test.go; additional files ONLY if unavoidable (report).
Set durable membership from full config before serving network or starting peer runners, and on explicit pair/unpair/config changes; surface durability error and prevent unsafe GC. Avoid daemon.mu -> network waits or inversions; plan existing syncPeersLocked carefully. New/re-paired peers exchange full baseline using existing reset index flow; persist baseline ACK only after durable baseline application, never from received index alone. Inspect peer queue: retry entries and delayed due work mean successful fetching or zero immediate failures alone is not proof baseline applied. Send exact ACKs only for verified durable records after apply; resend on reconnect/no-op cycles so lost ACK and restart converge. Batch ACKs, never per live file; avoid any ACK flush for normal file-only perf fixture. Bind target epoch/membership checkpoint to Hello/session or ACK handshake; never invent peer epoch from local membership. Call collector after ACK and periodically during normal sync (no standalone tight timer). Do not lose retired records/control on normal scan/group commits/reset/compaction.
Integration tests use real two daemons/transport and controlled folder clock where needed: deletion durable then both peers ACK and collect after retention; offline configured member blocks even after 30 days; lost ACK + restart resends; unpair/re-pair needs new baseline; baseline pending apply cannot GC.
